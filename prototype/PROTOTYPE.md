# Field Cards prototype

An iPad-first, PC-compatible voice and typed datasheet lookup. Run `npm ci`, then `npm run dev` with Node 22.13+; the default preview is http://localhost:5173. An HTTPS deployment is required for microphone use on an iPad accessing a remote host.

The catalogue contains 662 units extracted from the Wahapedia navigation for Adeptus Custodes, Necrons, Space Marines, Genestealer Cults, Tyranids, Imperial Agents and Imperial Knights. Optional armies/allied factions narrow both speech and typed matching; the selection is saved locally. This is a lookup filter, not an army-legality validator. The API retrieves unit pages on demand; only indexed URLs are allowed. Five representative cards have validated, dated source snapshots as fallback. A failed refresh is visibly labelled and does not overwrite a good cached card. Broader indexed units may contain unsupported source layouts; an index entry does not certify parser coverage.

Opened cards are cached in device memory and sessionStorage for the browser session, including across page reloads where supported. Repeat lookup bypasses the API entirely. Refresh deliberately bypasses this cache; a failed refresh retains the session card. Clear session cache ends this collection without deleting the army selection or unrelated browser data. Closing the browser session may remove these cards; this is a game cache, not durable saved squads. The server additionally keeps a bounded one-hour cache.

Speech currently uses browser SpeechRecognition with an en-GB locale. It may use a vendor online service. No app API key is needed, and this app does not store recordings. Safari on iPad and Chrome/Edge on PC are the intended device trials; browser availability and permissions vary. Typed lookup remains available. No custom cloud or on-device speech model has been benchmarked yet. The displayed lookup timer starts after the transcript arrives, so it excludes speech-service latency.

Layers: `lib/speech.ts` (replaceable recognition adapter), `lib/search.ts` (unit resolution), `lib/wahapedia.ts` (source parsing), `app/api` (server fetch/cache), `lib/types.ts` (card schema), and `app/page.tsx` (display). Photos/saved squads/vision/combat/sync are future additions. Imported strings are rendered as React text; upstream scripts and HTML are never inserted into the page.

The Custodian Guard header references a product photo served by Philibert, with a source link and icon fallback if unavailable. No reuse licence is asserted. Other units use a neutral header pending a curated image collection or user uploads.

Verification: `node scripts/verify.mjs` checks matching and parser behaviour against downloaded fixtures in ignored `.sites-runtime/samples`; `node scripts/verify.mjs --http` additionally checks a running local API. Fixture setup is in `scripts/import-samples.mjs`; do not regenerate snapshot dates without retrieving fresh source HTML. `npx tsc --noEmit` checks types, and `npm run build` creates the Cloudflare Worker output.

Remaining real-device checks: allow microphone; say the five example names; deny permission and recover; compare Safari tab/Home Screen mode; confirm portrait/landscape readability and speech accuracy with gaming-room noise. No claim of real microphone or iPad testing is made by automated checks.

Microphone troubleshooting update: the embedded PC preview reproduced a speech-service `network` error. A separate Test microphone control now uses getUserMedia and an audio level meter to isolate capture from transcription. It releases tracks after ten seconds, manual stop, cancellation or unmount; the test neither records nor uploads audio. Speech status distinguishes service startup from the audiostart capture event, and watchdogs recover from stalled services. `node scripts/verify-speech.mjs` checks these recognition lifecycle cases. A working input meter does not prove successful transcription; use a full Chrome/Edge window for the next PC speech trial.

Device check on 11 September: the local preview successfully opened the default HyperX QuadCast S microphone and detected a nonzero input signal. Capture was stopped through the UI and the test reported success. Speech transcription remains unverified; its embedded service returned a connection error. A separate Chrome browser is not connected to the available browser automation, so the user must perform that next trial.

Voice entry update: each new Tap to speak clears the previous query, blurs the input, and starts recognition synchronously from the button click. Interim transcripts update React state directly without input focus. The field is read-only with inputMode none during recognition. Final speech (or the last nonempty draft at a normal recognition end) triggers lookup exactly once. Failure/abort does not submit an incomplete draft. Fresh sessions never append the previous unit name. These event cases are covered by verify-speech; actual iPad keyboard behaviour still needs a device trial.

## Project design rules — September 2026

The persistent instructions are in AGENTS.md. Landscape iPad and desktop use a viewport-height workspace with search beside the card, compact stats, and collapsible army/ally selection, quick picks and microphone diagnostics. Long rules remain readable and scroll inside the card; expanded controls may scroll inside the lookup panel. Smaller viewports and enlarged text use the normal responsive page. This is a fit-first design, not a promise that every datasheet can be displayed simultaneously without scrolling. Actual iPad visual/fullscreen testing remains required.

Fullscreen uses the browser Fullscreen API from a direct button tap, follows fullscreenchange (including Escape), and catches rejection. Home Screen standalone support is retained. If unsupported, the UI explains Safari Share > Add to Home Screen. See [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Element/requestFullscreen) and [Apple's iPad guide](https://support.apple.com/en-ie/guide/ipad/ipad8f1f7a29/26/ipados/26).

Faction tokens live in lib/factions.ts: Custodes gold, Space Marines blue, Necrons green, Genestealer Cults violet, Tyranids plum, Imperial Agents crimson and Imperial Knights teal. Chaos Space Marines have a bronze token ready for future catalogue expansion; this does not add their units. Buttons, suggestions, banner and section headers share the tokens, with visible faction names. These are app identifiers, not universal lore or painting rules. Gold is informed by [GW's Custodes guide](https://www.warhammer-community.com/en-gb/articles/LRraZYf4/starting-an-adeptus-custodes-army-in-warhammer-40000-everything-you-need-to-know-from-painting-to-lore/), violet/plum by [GW's Tyranids showcase](https://www.warhammer-community.com/en-gb/articles/btcabhjs/the-tyranids-of-leviathan-painted-by-the-warhammer-community/) and faction publications. Knight/Agent accents are deliberate app distinctions; [Knight heraldry varies](https://www.warhammer-community.com/en-gb/articles/kk5fujft/starting-an-imperial-knights-army-in-warhammer-40000-everything-you-need-to-know-from-painting-to-lore/). Sources consulted 2026-09-11.

No gameplay rules or datasheet values changed. Future gameplay work must verify user examples against Wahapedia for the selected edition and retain source/date and cache warnings.

## 11th-edition migration — 2026-09-11 (supersedes earlier edition notes)

The app targets 11th edition. Rebuilt the seven faction indexes (656 units) and five saved examples from actual /wh40k11ed/ sources retrieved today. The importer checks both the requested source URL and page edition metadata, supports the new flat column layout, weapon keyword markup and core/army abilities. Rejected or unavailable sources produce a clear error or a dated saved 11th-edition copy, never silently substitute 10th edition. Old browser caches have a separate namespace and cannot be read by this version. Each newly requested card checks Wahapedia; repeat session lookups still use the session copy until Refresh or Clear session cache. A source retrieval is not a guarantee that Wahapedia has incorporated every official erratum.

Invulnerable saves appear as a shield below SV, with the label alongside. Values come from the source, not the Combat Patrol image reference. Tests cover edition mismatch rejection, 11th-edition index URLs, source abilities, weapon keyword extraction and session reuse. Actual iPad visual testing remains required.

Follow-up: removed app footer and permanent datasheet source footer. Source/date/Refresh remain in a sidebar disclosure, with edition on the banner and stale-copy warnings unchanged. Overscroll is contained at card, panel and page boundaries. The browser/OS retains control of fullscreen exit gestures; Home Screen standalone launch is the recommended stable app view. The Knight reference is a visual layout guide, not authority for stats or edition.

## Versus foundation — 2026-09-11

Routes: / is the two-tile home; /lookup is unfiltered lookup without army/ally controls or microphone diagnostics; /versus contains team setup and the staged engagement flow. Both use components/data-card.tsx, components/unit-search.tsx, the same parser, catalogue and session card cache. Eight factions are indexed, now including Adeptus Mechanicus. New source conditions are preserved in invulnerableCondition; parser/cache version 3 prevents old condition-free cards being reused. The save shield shares SV width and uses a curved mask with a faction-coloured label bar.

Team setup supports 1–4 players per side, one main army, one optional ally and one selected detachment per player. It saves the setup and fetched rule packs locally; Resume restores setup, not an unfinished attack. The faction rules endpoint fetches current 11th-edition rules, with dated, clearly flagged snapshots if unavailable. This is a group setup tool, not a legal roster builder; main faction rules are not automatically granted to allies. Source text may include FAQ/errata and players must review it. Standard detachments are separated from Boarding Actions/Crusade content.

The battle domain is separate in lib/battle.ts: Player, Game, Combatant, Weapon, Conditions and a future DiceObservation interface. No camera processing, random dice generation or casualty allocation is implemented. resolveAttack is a pure calculation returning roll targets, notes, weapon keywords and source-stat-derived values. The UI stages 75/25 attacker selection, 25/75 defender selection, 50/50 ready cards, condition review, and a roll-target summary. Weapon selection is restricted to the attacker; a return attack only accepts melee weapons. Multiple source profiles can be selected. Eligibility, ownership and review state are reconfirmed for a return attack; no automatic fight back is assumed, because fight order, survival, engagement and prior activations matter.

Verified numeric effects: 11th-edition S/T wound table; BS/WS and hit/wound modifier caps; AP and armour saves; ranged-only invulnerable eligibility; Cover worsens BS, Plunging Fire improves BS with its eligibility confirmed; Ignores Cover; Torrent; Heavy and Lance with confirmed conditions; Lions of the Emperor isolation excluding Vehicles; Martial Ka’tah melee stance reminders. Other army/detachment rules, unit abilities, critical effects, re-rolls, Feel No Pain and allocation remain visible manual reminders. The user must confirm conditions and can enter other net hit/wound/AP/armour-save adjustments. Do not describe this as a fully automatic rules engine or a casualty prediction. The next implementation should extend the typed effect evaluator and tests instead of interpreting arbitrary source prose as executable instructions.

Rules consulted 2026-09-11:
- https://wahapedia.ru/wh40k11ed/the-rules/core-rules/ (Attack Sequence, Benefit of Cover, Plunging Fire, Fight Step, Heavy, Lance, Ignores Cover)
- https://wahapedia.ru/wh40k11ed/the-rules/rules-appendix/#Modifiers (separate characteristic/roll modifications and caps)
- https://wahapedia.ru/wh40k11ed/factions/adeptus-custodes/ (Martial Ka’tah and Against All Odds)
- https://wahapedia.ru/wh40k11ed/factions/imperial-knights/Knight-Paladin (5+ against ranged attacks only)

Validation: verify-versus.mjs tests the above core calculations, eligibility exclusions, faction-pack extraction and conditional saves. Existing parser/search/cache and voice tests remain in use. Actual iPad microphone, touch, animation and layout trials are still needed; no claim of device verification is made.

## Touch layout refinement — 2026-09-11

Teams now offer one or two players only, including limiting restored older setups. App/stage headers and shared card banners are shorter, without reducing main touch targets below 44px. Fight is larger. Army/detachment details start collapsed and manual modifiers sit in an Advanced disclosure (marked active if nonzero). Attack result tiles use the attacker's faction for hit/wound and defender's faction for saves.

Versus recent-unit IDs are stored per game session ID and player ID, with at most twelve entries in most-recent-first order. They are filtered against the player's current main/ally catalogue and opened through the shared cached-card path. They do not contain other players' history or standalone lookup history. Role swapping keeps history attached to the player. New engagements retain history; new game IDs isolate it. Browser storage failure falls back to memory.
