# Project-wide rules

- Design for the user's 10.9-inch iPad Air in landscape first, then desktop monitors. Aim for a single viewport with an app-like layout. Keep primary search, voice, card stats and navigation visible. Use compact controls and disclosure for secondary tools before adding scrolling. Never hide rules, truncate essential text or shrink it unreadably to force a fit. Long datasheets, smaller windows and enlarged text may use clearly accessible internal scrolling or a responsive page fallback.
- Preserve fullscreen controls and Home Screen standalone support. Feature-detect fullscreen and provide an honest fallback; never assume iPad browser support. Voice entry must not focus the input or open the keyboard.
- Use the central faction palette in lib/factions.ts for all faction references: army choices, selected armies, unit suggestions, card banners and related accents. Keep faction names visible; colour alone is insufficient. These are UI identifiers inspired by faction imagery, not mandatory miniature paint schemes. New factions need a deliberate palette entry.
- Rules source is Wahapedia (the user has referred to it as Wikipedia in conversation). Verify any proposed gameplay rule, unit stat, loadout restriction or rules implementation against the relevant Wahapedia page for the app's edition, even when the user gives an example. Record source URL and retrieval date. Treat user examples as hypotheses, not verified rules. If unavailable or ambiguous, state that and do not invent a rule. Do not silently mix editions; official Games Workshop errata may be used to investigate discrepancies, which must be disclosed.
- Preserve session caching and source provenance. A cached/snapshot card is not freshly verified; show its date/mode and keep Refresh available. No gameplay rule changes are implied by a visual change.
- Keep the prototype usable on PC and iPad; retain typed lookup and local session storage. Keep future squad, image and dice features separate from canonical source data.

- Target 11th edition exclusively. Verify page edition before importing. Never relabel 10th-edition values as 11th. If a different edition must be shown, explicitly label it on the card and warn the user; prefer an unavailable message. Source freshness means latest retrieved Wahapedia content, not a guarantee of upstream errata completeness. Keep Refresh and source date available. Place any source-provided invulnerable save beneath SV in the header, using a shield badge and visible label. Do not infer values from reference images, including Combat Patrol cards.

- Maximise card space: omit app footer and permanent source footer. Keep source URL, retrieval date, edition and Refresh accessible in a compact disclosure; never hide fallback warnings. Contain overscroll within panels, but do not promise a web page can lock iPadOS fullscreen or override system exit gestures. Prefer Home Screen standalone mode for stable app use.

- Share DataCard, UnitSearch, parser and source cache between lookup and Versus. Keep game state, rule source text, typed effect calculations and future dice observations separate. Never execute arbitrary rule prose as code or automatically grant main-faction rules to allies. Unimplemented effects must stay visible as manual reminders. A melee return attack requires eligibility confirmation rather than unconditional swapping. Preserve the home, lookup and Versus routes.

- Teams support only one or two players. Keep rule details and Advanced manual modifiers collapsed initially. Use attacker faction colours for hit/wound result tiles and defender colours for save tiles. Keep Versus recent cards scoped by game and player, filtered to their current main/ally factions; never leak another player's selections into quick picks. Minimise decorative headers while preserving readable conditional-save labels and large touch controls.

- Battle condition choices use large, icon-led toggle tiles with visible benefits and expandable eligibility text. Keep mutually exclusive stances exclusive. Reset confirmation after changing a condition; show the central Resolve action only once players confirm.
- Roster drafts and pasted exports are local player state, separate from canonical cards. Preserve draft text across reloads; parse text as data only, cap input size, and require explicit review before replacing selected units. Never silently guess ambiguous unit names or count nested weapon bullets as models.
- Roster points must use dated 11th-edition source tables, including repeat-unit tiers and composition choices. Mark chapter/army-dependent or missing costs unverified instead of selecting an arbitrary price. Do not claim roster legality or enhancement/loadout support.
- Pre-cache roster cards through the shared card loader and show roster/recent quick picks only for the selected player's current main/allied factions. Keep source image URLs and attribution separate from rules. Fetch images lazily; keep any processed image cache bounded, preserve the original on failure, and never substitute a differently named miniature as a missing unit photo.
